# 工作区文件记忆规范 v2.3

> 适用对象：个人在 DSH 中管理的开发项目与运维工作区。**知识/学习类目录不在范围内**（见 §8）。
> 载体：纯 Markdown 文件（`AGENTS.md` + `docs/`），进 git，零运行时依赖。
> 本规范配套技能：`project-memory-init`（自动生成骨架 + 自检）。
> v2.3 相对 v2.2：新增 §9.12「文档生命周期」与 §9.13「脚手架的坑」；AGENTS.md 增加 3 条通用规则（grep 引用、单一活跃载体、公开前查历史）；校验清单补 2 项。
> v2.2 相对 v2.1：**移除知识类工作区**——不再生成 NOTES.md 与知识型 AGENTS.md；知识/学习目录改为「不初始化」，靠 session_search 与按主题手写 notes 代替。理由见 §8。
> v2.1 相对 v2.0：新增「定位与边界」、本机私有覆盖层、任务形状读取、跨工具/嵌套 AGENTS、证据平衡、临时工作区 opt-out；明确「自动生成只出骨架，需人工审阅」。
> v2.0 相对 v1.2：新增运维工作区与 `RUNBOOK.md`；新增「边界与红线」节；触发器按类型分版；补齐拒绝写入清单、复验与归档、并发与快照操作步骤、跨机器同步。

## 0. 适用边界（先读）

这套体系解决的是：**同一工作区的不同会话之间，信息丢失、重复解释、旧结论污染**。
它**不承诺**提升任务成功率，也不替代代码、README 或工单系统。

三条边界：

1. 只写「对该工作区任何会话都恒真、且不能从代码/文件中直接推导」的内容；仓库概览、进度、临时状态一律去动态层。
2. 必须每次生效的规则放 `AGENTS.md`（每次会话自动注入）；自动记忆、向量检索、会话摘要只做补充，不做唯一真源。
3. 文件是唯一共享记忆：能进 git、能被其他工具读、能被人工审 diff。不要引入数据库、向量库、插件或联网服务。

**证据边界**：2026 年的三项研究结论并不一致——有研究发现 AGENTS.md 关联运行时间 −28.6%、输出 token −16.6%；另两项发现任务成功率没有显著提升、推理成本 +20% 以上，且「仓库概览」类内容没有帮助。因此本规范只承诺**减少重复解释、保留不可推导的约定与历史**，不承诺正确率提升；任何「加文件能提效」的说法都应先做小规模对照。详见 §13。

**强度边界**：`AGENTS.md` 是模型上下文，不是强制配置；高风险的硬约束必须下沉到 linter / formatter / CI / hook / 权限系统，而不是只写一句话。

## 1. 三类工作区与文件矩阵

| 文件 | 角色 | 变更频率 | dev | ops | 长度预算 |
|---|---|---|---|---|---|
| `AGENTS.md` | 宪法/索引 | 极低 | ✅ | ✅ | ≤ 60 行 |
| `docs/PROGRESS.md` | 工作日报 | 每次工作 | ✅ | ✅ | ≤ 120 行，已完成 ≤ 30 条 |
| `docs/KNOWN-ISSUES.md` | 坑与故障 | 踩坑即记 | ✅ | ✅ | ≤ 120 行，已修复 ≤ 20 条 |
| `docs/DECISIONS.md` | 决策与理由 | 定案即记 | ✅ | ✅ | ≤ 300 行 |
| `docs/RUNBOOK.md` | 可重复操作步骤 | 低频 | 可选¹ | ✅ | ≤ 300 行 |
| `AGENTS.local.md` | 本机私有覆盖（不提交） | 按机器 | 可选 | 可选 | ≤ 20 行 |
| `docs/local/` | 本机私有笔记（不提交） | 按机器 | 可选 | 可选 | 按需 |

¹ 开发项目若含部署/发布/服务器操作，追加 `RUNBOOK.md`，主类型仍为 `dev`。
旧项目已有 `AGENTS.md` 时只补缺，不改写已有保护节；历史文件不删除，停用就在指针里标「已停用」。
`AGENTS.local.md` 与 `docs/local/` 必须写进 `.gitignore`；只放本机路径/端口/工具差异，不放密钥。

## 2. 五条原则

1. **文件优先**：对话易失，文件持久；值得跨会话记住的东西必须落盘。
2. **稳定层 / 动态层分离**：`AGENTS.md` 只放恒真事实；进度、坑、决策、操作步骤各归其位。
3. **准入判据**：只写「对该工作区任何会话都恒真 + 不能从代码/文档直接推导」的内容。两条缺一，不进稳定层。
4. **拒绝写入清单**【禁止】：
   - 密钥、令牌、密码、账号、私钥、cookie（只写获取位置）
   - 未验证的推断、无来源的结论、LLM 生成的仓库概览
   - 一次性状态、临时方案、当前分支/会话状态（→ PROGRESS）
   - 模糊要求（「代码写好一点」）、可从代码直接看出的目录清单
   - 大段原文抄录、聊天记录全文
5. **零依赖**：只依赖 Markdown 阅读器与 git；校验脚本只读、无网络、无安装。
6. **索引常驻、正文按需**：`AGENTS.md` 只放「有什么文件、什么时候读」的压缩索引；主题内容放 `docs/`，按任务形状读取，避免每轮把全部文档塞进上下文。

## 3. AGENTS.md 规范

### 3.1 结构（类型差异由技能拼装）

```text
# <工作区名>
> 类型: <开发/运维> · 规范: project-memory-init/2.3 · 建立: YYYY-MM-DD · 最后核对: YYYY-MM-DD
> <一句话说明>

<类型专属节>

## 工作约定
## 边界与红线
## 进度衔接（必须保留本节原文）
## 自维护触发器（必须保留本节原文）
## 记忆文件
```

类型专属节：

- **dev**：定位与边界 / 技术栈 / 常用命令 / 项目结构
- **ops**：管理对象 / 环境与访问 / 危险操作红线 / 常用操作

本规范只有这两类。知识/学习类目录不属于适用范围，见 §8。

「定位与边界」写「是什么、给谁、不做什么」，不是 README 概述；只有稳定且不可从代码推导时才写。
「边界与红线」四行所有类型通用：不写秘密；不把推断当结论；复述后未经确认不自动开工；改记忆文件用编辑工具且并发先读。

「记忆文件」节只放指针，不摘抄内容：每行写「文件 + 何时读」；进度、已知坑、决策三行必写；有 RUNBOOK 时加一行；本机私有覆盖单独一行。

### 3.2 写作守则

- 一条一行、祈使句、可执行；每条能回答「照着做了吗」。
- 目标 40～55 行，硬上限 60 行；每行都按会话轮次付 token。官方与研究建议是「越短越好」：Claude Code 建议单文件 <200 行，HumanLayer 的根文件 <60 行。
- 措辞分档：**禁止** = 会造成泄漏/数据丢失/污染；**必须** = 有触发条件且可检验；**建议** = 可裁剪。全文「必须」条目控制在 10 条以内。
- 具体到命令/路径/字段，不写「注意维护好」。
- 不复制 README（README 给人，AGENTS.md 给 agent）；不写仓库概览/完整目录树，只写非显而易见的归属与放置规则。
- 风格/格式规则优先交给 linter / formatter / CI；AGENTS.md 只写工具无法强制的约定。
- 能指向 `file:line` 的写指针，不贴会过期的代码片段。

### 3.3 反模式（禁止）

- 写当前进度、本周计划、最近改动（→ PROGRESS）
- 示例命令当成项目命令（初始化时只从模板复制，示例块禁止复制）
- 子目录与根 AGENTS.md 对同一主题写两份规则（软语义，会打架）
- 仓库概览、完整目录树、逐文件说明（研究显示无益且增加成本）
- 把 linter 能做的事写成自然语言要求（「两空格缩进」「必须过 eslint」）
- 超过一屏的背景介绍；密钥明文；无来源的数字
- 为了更新而更新（见 §9.3 周报警线）

### 3.4 保护节

「进度衔接」「自维护触发器」两节含「（必须保留本节原文）」标记，生成后**逐字保留**，不得增删改；技能校验脚本会比对原文。
触发器按类型分版（dev / ops），其原文见附录 A。

### 3.5 嵌套 AGENTS.md（monorepo / 大型项目）

- 根 `AGENTS.md` 只放全仓通用规则（≤60 行）；子目录 `AGENTS.md` 只放该子目录特有内容（≤30 行）。
- 同一主题只在一个层级写；根与子目录冲突时，不同工具行为不同，不能依赖「就近覆盖」自动解决。
- DSH 的加载方式是「根 → 当前目录整条链」都读入，不是只读最近一份；因此重复/矛盾会同时进入上下文。
- 生成器默认只建根文件；只有用户明确要求或 monorepo 信号很强时，才建议按包补子目录文件。

### 3.6 跨工具兼容

- `AGENTS.md` 是跨工具入口：Claude Code 在没有 `CLAUDE.md` 时直接读它；Gemini CLI 可通过 `context.fileName` 配置；Codex/Cursor/Zed 等也支持。
- 默认**不生成** `CLAUDE.md` / `GEMINI.md` 副本；确实需要时只放一行导入或指针（如 Claude Code 的 `@AGENTS.md`），绝不复制内容。
- 不同工具对「就近覆盖」「强制程度」的实现不同；跨工具时把关键约束同时放进 linter/CI，而不是只靠文件。

## 4. docs/PROGRESS.md

### 4.1 结构

```markdown
# PROGRESS — <工作区名>
> 最后更新: YYYY-MM-DD HH:mm

## 当前状态      ← 1~3 句：进行到哪、在做什么、卡在哪
## 已完成        ← [YYYY-MM-DD] 动词开头 + 关键文件/PR 路径；新条目放最上
## 下一步        ← [ ] 具体到「打开哪个文件、做什么」；禁止「继续完善」
## 已知问题      ← 未解决 bug、技术债、待定决策（可选）
```

### 4.2 更新纪律

- 完成任一可交付单元、计划变更、会话结束前（**哪怕任务夭折**）都要更新。
- 「当前状态」只写最新事实；被取代的旧状态移入「已完成」。
- 带日期；按时间倒序；附相对路径。
- 并行会话写前必须 `read` 最新版再改（读-改-写），否则后写覆盖先写。
- 「最后更新」距今 > 7 天且项目仍在动 → 收尾时提醒用户核对。

### 4.3 归档

「已完成」> 30 条 → 旧条目移入 `docs/archive/progress-<年份>.md`（移动，不删除）。

## 5. docs/KNOWN-ISSUES.md

### 5.1 结构

```markdown
# 已知坑 — <工作区名>
> 高频动态文件：踩坑即记，允许频繁变更。每条必须含 现象 / 原因 / 规避。

## 坑列表（新坑放最上）
- [YYYY-MM-DD] 现象: …；原因: …；规避: …

## 已修复
- [YYYY-MM-DD] <修复结论与关键改动>
```

### 5.2 纪律

- 踩坑解决或排障出结论时即记；三要素（现象/原因/规避）缺一不可。
- 「已修复」> 20 条 → 移入 `docs/archive/known-issues-<年份>.md`。
- 过时条目不得静默留着：复核后选「保留 / 归档 / 删除」之一。
- 运维场景中，事故与故障也可记这里；长流程放 RUNBOOK，结论与坑放这里。

## 6. docs/DECISIONS.md

### 6.1 结构（轻量 ADR）

```markdown
# 决策记录 — <工作区名>
> 低频稳定文件：记录「为什么这么做」。已定案条目不改写；被取代时新起条目并标注「取代 <日期> 决策」。

## 决策列表（新决策放最上）
- [YYYY-MM-DD] 一句话摘要（状态: 生效）

### [YYYY-MM-DD] <决策主题>
- 背景: 要解决什么问题
- 决策: 做了什么选择
- 备选: 考虑过什么、为什么否决
- 原因: 一句话核心理由
- 状态: 生效 / 已被 <日期> 决策取代
```

### 6.2 纪律

- 做出影响后续工作的选择时，定案即记；每个决策约 2 分钟。
- 历史不可篡改：不改旧条目；推翻时新增条目并标明取代关系。
- 「为什么」优先于「做了什么」；不写会议流水账。
- 区分两类更新：**事实变化**（命令、边界、约束）要**改写**旧事实；**决策历史**要**追加**新条目并标取代，不重写旧条目。

## 7. docs/RUNBOOK.md（运维 / 可选）

### 7.1 结构

```markdown
# RUNBOOK — <工作区名>
## 管理对象        ← 对象 / 角色 / 入口（凭据只写位置）
## 日常操作        ← 每步可复制执行
## 故障排查        ← 按症状索引
## 备份与恢复
## 变更与回滚      ← 每次变更前写回滚方式
```

### 7.2 纪律

- 只写「怎么做」；「为什么」→ DECISIONS。坑与事故结论 → KNOWN-ISSUES。
- 危险步骤必须有：前置检查、确认点、回滚方式；未演练的命令不进生产。
- 步骤保持可复制；主机名/路径/端口写实际值，不写「相应目录」。
- 环境差异（生产/测试）单独标注；所有凭据只写获取位置。
- 对象超过 15 个时按系统拆分文件，RUNBOOK 保留索引。

## 8. 知识/学习类目录：不初始化（设计决策）

### 8.1 决策

v2.2 起，知识/学习类目录**不再初始化记忆体系**，也不再生成 `docs/NOTES.md`、知识型 `AGENTS.md`。
需要留结论时，按主题手写 `docs/notes/<主题>.md`，不作为本规范的一部分。

### 8.2 理由

知识目录的典型形态与项目目录相反：**一个目录里跑多个不同主题的会话**。本体系的三个核心机制在它身上全部失效：

| 机制 | 失效方式 |
|---|---|
| `PROGRESS.md`（当前状态/下一步） | 线性项目进度模型；多主题并行时"当前状态"无解，两个会话收尾还会互相覆盖 |
| `KNOWN-ISSUES.md` / `DECISIONS.md` | 知识会话不产生"坑"和"架构决策"，长期是空文件 |
| 「进度衔接」保护节 | 强制每次开工复述进度，但知识会话没有"当前进度"，纯噪音 |

加上稳定层（技术栈/命令/危险操作）在知识目录几乎为空，`AGENTS.md` 大部分是空转 token。研究结论也支持"少即是好"：上下文文件总体不提升成功率、成本 +20%，只有非标准约定有价值（§13）。

### 8.3 替代做法

- 回查历史会话：用 `session_search`（按工作区检索）或 `@` 会话引用；不必为了"记得"而建文件体系。
- 值得长期保留的结论：按主题写成 `docs/notes/<主题>.md`，一个主题一个文件，避免并发写冲突；每条带来源与日期，区分事实/推断/观点。
- 若某个主题确实变成长期项目（有代码、有部署、有进度），再按 §10.1 初始化为 `dev` 或 `ops`。

## 9. 维护闭环

### 9.1 触发器 → 写入位置

| 事件 | 更新 |
|---|---|
| 项目定位/非目标变化 | AGENTS.md「定位与边界」 |
| 依赖/框架变化 | AGENTS.md「技术栈」 |
| 脚本命令变化 | AGENTS.md「常用命令」 |
| 核心目录重组 | AGENTS.md「项目结构」 |
| 管理对象/访问入口变化 | AGENTS.md「管理对象」「环境与访问」 |
| 运维步骤变化 | docs/RUNBOOK.md + AGENTS.md 触发器对应行 |
| 踩坑/故障结论 | docs/KNOWN-ISSUES.md |
| 架构/方案/取舍定案 | docs/DECISIONS.md |
| 进度变化（每会话） | docs/PROGRESS.md |

### 9.2 收尾三件套 + 人工门禁

会话收尾按顺序问自己三句：

1. `PROGRESS.md` 更新了吗？（必须）
2. 本次踩坑/决策了吗？（是 → 对应文件）
3. 本次触发 AGENTS.md 触发器了吗？（是 → 收尾批量改一次）

人工门禁：用户收尾时问一句「PROGRESS.md 更新了吗？」；agent 汇报时必须显式说明更新了哪些记忆文件。

### 9.3 批量提交与周报警线

- 一次会话最多产生 **1 次** `AGENTS.md` 变更；触发多处时收尾统一改。
- 每自然周 `AGENTS.md` 变更 > 1 次 = 内容放错层：把最活跃的节降级到 `docs/`，并在 PROGRESS 记录这次降级。

### 9.4 快照陷阱【必须】

- 当前会话里的 `AGENTS.md` 是加载时快照；只有 `read`/`write`/`edit` 成功后才可能刷新。
- 修改记忆文件必须用 `read`/`write`/`edit` 工具，**禁止**用 bash `sed`/`cat >`/外部编辑器改完就当已生效。
- 若已在会话外修改：立即让 agent `read` 一遍，再继续工作。

### 9.5 并发写【必须】

- 同工作区并行多会话时，写前必须 `read` 最新内容，基于最新版修改（读-改-写）。
- 无法协调时约定「同一时刻只有一个会话负责记忆文件」。
- 冲突时保留双方事实，手工合并；禁止直接覆盖。

### 9.6 执行节制

- agent 开工复述进度后，未经用户确认不得自动开始执行「下一步」。
- 「下一步」是给用户看的选项，不是自动任务队列。

### 9.7 复验、归档、降级

- 动态层条目超过 30 天未复验 → 收尾时提示复核；处置必须三选一：保留 / 归档 / 删除，禁止「先放着」。
- 归档 = 移动到 `docs/archive/`，不删除。
- 文件超预算时：把最活跃的节降级到 `docs/`（指针留在 AGENTS.md），并记录到 PROGRESS。

### 9.8 安全

- 任何记忆文件都不写明文秘密；只写「在哪找」（`.env`、密码管理器条目名、CI secret 名）。
- 公开仓库尤其注意：记忆文件会进 git 历史；误提交后需轮换凭据，而不只是删文件。
- 涉及生产环境的操作记录，只写步骤与结果，不贴完整命令输出中的敏感值。

### 9.9 多工具协作

- `AGENTS.md` 是默认跨工具入口；Claude Code 在没有 `CLAUDE.md` 时会直接读它，Gemini CLI 可配置文件名，Codex/Cursor/Zed 等也支持。
- 其他工具对「必须保留本节原文」等约定只是普通文本，不会强制；对它们按「降档」对待，关键约束同时放进 linter/CI。
- 默认不生成 `CLAUDE.md` / `GEMINI.md` 副本；确实混用时只放一行导入/指针（如 `@AGENTS.md`），绝不复制内容。
- 同一主题只在一个文件写；跨工具重复会造成漂移。

### 9.10 任务形状读取（按需加载）

开工只必读两个：`AGENTS.md` + `docs/PROGRESS.md`。其余按任务形状读，不预加载：

| 任务 | 再读 |
|---|---|
| 改代码/加功能 | 最近的目录 AGENTS.md（如有）、相关源码；需要时 `DECISIONS.md` |
| 排障/修 bug | `KNOWN-ISSUES.md`；涉及运维再加 `RUNBOOK.md` |
| 架构/方案取舍 | `DECISIONS.md`；必要时回看 `KNOWN-ISSUES.md` 的历史教训 |
| 运维操作 | `RUNBOOK.md` + `AGENTS.md`「危险操作红线」 |
| 收尾 | `PROGRESS.md`（必写）+ 本次触发文件 |

不是每次都要把所有 docs 读一遍；索引常驻、正文按需，是控制 token 与漂移的关键。

### 9.11 本机私有覆盖层

多台电脑（家里/公司/出差）时，把**只对本机成立**的差异放私有层，不污染项目共享记忆：

- `AGENTS.local.md`（项目根，DSH 会与 `AGENTS.md` 一起加载）：本机路径、端口、代理、工具位置、账号别名（不写密钥）。
- `docs/local/`：本机临时笔记、本机特有的排查记录。
- 两者都写进 `.gitignore`；提交前确认没有被 `git add -A` 带进去。
- 项目通用规则仍写 `AGENTS.md`，私有层只写差异，避免双份维护。
- 换机器时只同步 `AGENTS.md`/`docs/`（git），私有层各机器自己维护。

### 9.12 文档生命周期：新增 / 移动 / 删除 / 归档

记忆体系只**增加**载体、不**删减**用户的既有文档。四类动作各有前置条件：

| 动作 | 前置条件 |
|---|---|
| 新增 | 先查是否已有同主题载体；有就改旧的，不新建（避免双真源） |
| 移动 | 先 `grep -rIl` 找引用（代码注释、README、配置），移动后同步改完再提交 |
| 删除 | 只有确认内容已失效且无人引用才删；优先归档而非删除 |
| 归档 | `git mv` 到 `docs/archive/`，并在活跃文档留一行指针；归档文件不再更新 |

三条硬规则：

1. **单一活跃载体**：同一主题只有一个"当前有效"文档；新旧并存时必须在新文档标注"取代 YYYY-MM-DD 版本"。
2. **删除前先查引用**：`grep -rIl --exclude-dir=.git --exclude-dir=node_modules "<文件名>" .`；有引用先改引用。
3. **不为了"干净"删业务文档**：业务文档（设计规格、审查报告、问题清单）是记忆文件的素材来源；AGENTS.md 用指针引用，不复制、不删除。

### 9.13 脚手架/生成器自身的坑

这些坑只在"生成记忆文件"这一步出现，但会造成真实污染：

- **文件名即加载**：`AGENTS.md`、`AGENTS.local.md`、`CLAUDE.md` 会被工具自动加载。模板、示例、备份**不能**用这些名字——放 `templates/` 并改名（如 `AGENTS.local.template.md`）。
- **占位符形态**：文档里的 `<主题>`、`<路径>` 会被读者和校验器当成"未填模板"。写示例用 `{主题}` 或放进代码块。
- **副本会漂移**：规范/模板的副本必须标注"来源 + 快照日期"；改源后同步，能不放副本就不放。
- **校验器要能说"不适用"**：对未初始化目录、opt-out 目录、知识/学习目录应输出"跳过 exit 0"，而不是报一堆缺文件 ERROR。
- **负向测试**：保护节被改、明文凭据、模板残留、拒绝路径都要有用例，不能只测"生成成功"。

## 10. 初始化、迁移与跨机器

### 10.1 新工作区

1. 用 `project-memory-init` 技能：说「初始化项目」或 `/project-memory-init`。
2. 技能侦察 → 判定类型 → 生成 → 自检 → 汇报待补项。
3. 用户补齐 `（待补充）`，`git init` + commit（是否执行先问）。
4. 在新会话中验证：开工应自动读 PROGRESS 并复述。

**知识/学习类目录不初始化**（§8）：技能命中知识信号时停止并说明，不生成任何文件。

**临时/探索工作区**（例如 `default`）：在根目录放 `.dsh/no-project-memory` 空文件，或在 `AGENTS.md` 顶部写 `> 记忆: 关闭`；技能识别后不生成任何文件。临时内容不需要跨会话共享时，不要初始化。

**安装方式**：可以只用技能目录（`~/.dsh/skills/project-memory-init`），也可以安装为 bundle 插件（UI「添加插件」粘贴 Git 仓库地址），见 README。

### 10.2 已有项目升级（v1.2/v2.0 → v2.1）

1. 先 `read` 现有 `AGENTS.md` 与 docs，备份或确保已提交。
2. 只做增量：补「定位与边界」「边界与红线」「记忆文件」、把「触发器」升级为对应类型原文、补 RUNBOOK（如需要）。
3. 不动已有的「进度衔接」；不删除任何历史文件；旧文件没有类型行时只补类型行，不编造日期。
4. 升级后跑校验脚本；变更写进 PROGRESS，理由写进 DECISIONS。
5. 本机差异迁移到 `AGENTS.local.md`/`docs/local/`，并加入 `.gitignore`。

### 10.3 类型切换

- 工作区从 dev 变 ops（或反之）：改 AGENTS.md 顶部类型与专属节；旧专属节降级到 docs/ 并标「已停用」，不直接删。
- 学习目录转为项目：先按 §10.1 初始化为 `dev`；旧笔记留在 `docs/notes/`（或原地），不要把笔记内容搬进 AGENTS.md。

### 10.4 跨机器与多人

- 推荐：把工作区（含记忆文件）放进 git 私有仓库，作为跨机器同步通道；开工前 `pull`，收尾后 `commit + push`。
- 不同机器同时编辑 → 按 §9.5 读-改-写；合并时保留双方事实。
- 机器相关差异（路径、端口、代理、工具位置）放 `AGENTS.local.md` / `docs/local/`，不进 git；每台机器自己维护。
- 不想把记忆文件进项目仓库时：单独建一个 `memory` 仓库/目录同步；但必须保证路径稳定、可追溯。
- 用户级全局偏好放 `~/.dsh/AGENTS.md`（≤ 20 行），只放跨项目恒真的内容；项目内容不放全局。
- 同时安装「纯 skill」与「bundle 插件」时，只保留一种来源，避免同名 skill 双份候选。

## 11. 验收自检表

每次收尾或每周一次：

- [ ] PROGRESS「当前状态」是最新事实，「最后更新」已刷新
- [ ] 本次踩坑 → KNOWN-ISSUES 三要素齐全；本次决策 → DECISIONS 四字段齐全
- [ ] 本次触发触发器 → AGENTS.md 已在收尾批量更新（本周 ≤ 1 次）
- [ ] AGENTS.md ≤ 60 行；两个保护节原文未被改动；「定位与边界」存在
- [ ] 无明文密钥/令牌；无 `<...>` / `{{...}}` 模板残留
- [ ] 动态层无超过 30 天未复验的条目（有则保留/归档/删除）
- [ ] 并行会话写前已 read；会话外改过文件已 read 刷新
- [ ] 类型专属文件齐全：ops 有 RUNBOOK
- [ ] 本机差异已放 `AGENTS.local.md`/`docs/local/` 且被 `.gitignore` 覆盖
- [ ] `（待补充）` 数量在减少；没有假装完整
- [ ] 删除/移动过文档或代码 → 已 grep 引用并同步更新
- [ ] 记忆文件里的指针全部指向真实存在的文件（无死链）
- [ ] 收尾汇报中明确说明更新了哪些记忆文件

校验命令：

```bash
node scripts/verify-memory.mjs <工作区根目录>
```

校验器对三种情况输出「跳过」并 exit 0：已标记不初始化、知识/学习类目录（§8）、未初始化且无开发/运维信号。

强档（可选）：把同一命令放进 git pre-commit 或 CI，改动源码时要求记忆文件同步变更；关键规则同时配置 linter/hook，不只写文字。

## 13. 依据摘要（结论 + 强度）

- 【强，负面】arXiv 2602.11988：仓库级上下文文件**总体不提升成功率**，平均推理成本 **+20% 以上**；指令会被遵守，但「仓库概览」无帮助。→ 禁止仓库概览，只写不可推导的约定。
- 【中，正面】arXiv 2601.20404：10 仓库/124 PR 上，有 AGENTS.md 时中位运行时间 **−28.64%**、输出 token **−16.58%**，完成行为相当。→ 精确命令与约定可能有成本收益。
- 【中，中性】arXiv 2607.27250：2 agent/17 任务/288 次运行，正确率无显著变化（≤10–15pp）；失败主要来自实现能力而非缺仓库知识。→ 不要承诺成功率，控制体积。
- 【中】Vercel eval：压缩的 AGENTS.md 文档索引 100%，skills 最高 79%；56% 的 eval 中 skill 未被调用。→ 常驻压缩索引可靠；初始化技能仍需显式触发/fallback。
- 【中】Claude Code 文档：CLAUDE.md 目标 <200 行；导入不减少上下文成本；auto memory 每 repo 一份、机器本地、首 200 行/25KB；指令是 context 不是 enforced config。→ 小文件、显式触发、硬约束下沉。
- 【中】HumanLayer：根 CLAUDE.md <60 行；渐进披露；不要把 linter 工作交给 LLM；不要自动生成定稿。→ 技能只出骨架，人工审阅。
- 【中】Cline Memory Bank 六文件、Operator Memory 三区（private/shared/user）、agentsge `.agents/` 索引：分层与索引是主流。→ 本机私有层 + 压缩索引。
- 【强，实操】上述三条通用规则（grep 后再删/移、单一活跃载体、公开仓库前查历史）均来自真实事故：文档被代码引用后删除导致悬空、新旧问题清单双真源、force-push 后旧提交在转 public 时暴露邮箱。
- 【强】知识/学习类目录不适合本项目记忆体系：多主题并行与线性进度模型冲突；以 §8 的替代做法为准。
- 【弱】归档阈值（30/20 条）与 30 天复验是经验值，可按项目调整；调整后写进 DECISIONS。
